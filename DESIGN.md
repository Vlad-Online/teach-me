# teach-me — прототип: изучение европейского португальского по видеофрагментам

Статус: этапы 0–2 реализованы (сборщик, трей, голос). Как запускать — в README.md.

**Отличия реализации от первоначального плана**
- Скачивание фрагментов (`--download-sections`) на YouTube зависает, поэтому видео скачивается
  целиком в 480p, клипы режутся локально, исходник удаляется.
- Автосубтитры YouTube (json3) уже содержат пунктуацию, смену говорящего и тайминг каждого слова,
  поэтому `whisper-1` для уточнения границ не нужен. Текст клипа уточняется через `gpt-4o-mini-transcribe`.
- Во многих видео субтитры вшиты в картинку. Кадр проверяется моделью с vision, полоса с текстом размывается.
- `Ctrl+Space` регистрируется только пока открыта карточка (иначе ломает автодополнение в IDE).
Окружение: Windows 11 **ARM64**, Rust `aarch64-pc-windows-msvc`, ffmpeg и mpv есть, yt-dlp нужно поставить.

**Принятые решения**
- Уровень A2–B1 → отбираем реплики по 3–8 слов, разговорные конструкции и простые новостные фразы.
- UI: Tauri 2 (WebView2).
- Голос: push-to-talk по глобальной горячей клавише (держишь — запись, отпустил — отправка).
- Источники: новости, сериалы и шоу, влоги и интервью, свои файлы из `inbox/`.

---

## 1. Общая схема

Один Cargo workspace, три крейта:

```
teach-me/
├─ crates/
│  ├─ core/        # БД (SQLite), модели, SRS-планировщик, клиент OpenAI, проверка ответа
│  ├─ harvester/   # CLI: источники → субтитры → отбор фраз → нарезка клипов → перевод → БД
│  └─ app/         # фоновое приложение в трее (Tauri 2): таймер, всплывающее окно, голос
├─ data/
│  ├─ teach-me.db
│  └─ clips/       # <id>.mp4, 480p, 2–6 сек, ~150–300 КБ каждый
├─ sources.toml    # список каналов/плейлистов/видео
└─ config.toml     # интервалы, горячие клавиши, модели OpenAI, лимиты
```

Сбор базы (harvester) и тренировка (app) разделены: тяжёлая работа (скачивание, ffmpeg)
выполняется разово/по расписанию, а фоновое приложение только читает готовые клипы из SQLite.

## 2. Источники видео (pt-PT)

- **YouTube** через `yt-dlp`: каналы португальских СМИ (RTP, SIC Notícias, CNN Portugal и т.п.),
  отрывки португальских сериалов и шоу. Важно: автосубтитры YouTube не различают pt-PT и pt-BR,
  поэтому фильтруем по **белому списку каналов из Португалии**, а не по коду языка.
- **RTP Play** — у yt-dlp есть экстрактор RTP; много бесплатного контента общественного ТВ Португалии.
- **Локальная папка `inbox/`** — сюда можно положить свои видеофайлы с `.srt`/`.vtt` (или без них —
  тогда распознаём речь сами). Поиск и скачивание с торрент-трекеров автоматизировать не будем.

Ключевая экономия: сначала качаем **только субтитры** (`--skip-download --write-subs --write-auto-subs`),
отбираем фразы, и только потом скачиваем **нужные фрагменты** (`--download-sections "*12.3-16.1"`),
а не целые серии.

## 3. Отбор популярных фраз

Субтитры → нормализованные реплики → оценка → топ-N.

1. **Парсинг VTT/SRT**. У автосубтитров YouTube «бегущие» дубли строк — их склеиваем; реплики
   режем на предложения по пунктуации и паузам.
2. **Кандидаты**: целые реплики (3–8 слов для A2–B1, 1.5–6 сек) и устойчивые n-граммы (2–5 слов).
3. **Оценка** кандидата:
   - частота точной фразы по всему корпусу («Pois é», «Está bem», «Não faz mal», «Tens razão»…);
   - частотность слов по общему частотному словарю португальского (фраза из частых слов полезнее);
   - бонус за разговорные конструкции, штраф за имена собственные, числа, редкие термины;
   - разнообразие: не больше K клипов на одно видео, дубли одной фразы из разных видео
     сохраняем как альтернативные клипы (одна и та же фраза разными голосами — это плюс).
4. **Уточнение границ и текста**: автосубтитры неточны по таймингу, поэтому фрагмент с запасом ±1.5 с
   прогоняем через OpenAI `whisper-1` с пословными таймкодами — получаем точный текст и точные
   границы клипа. Стоимость — доли цента на клип.

## 4. Нарезка и перевод

- `ffmpeg`: вырезка с полями −0.3/+0.4 с, 480p, H.264 CRF 28, AAC 64k, нормализация громкости
  (`loudnorm`), чтобы клипы звучали одинаково.
- Обогащение через дешёвую текстовую модель OpenAI (класс mini/nano, имя модели в `config.toml`),
  ответ в JSON:
  - основной перевод на русский + 2–4 допустимых варианта;
  - разбор: ключевые слова, особенности pt-PT (например, «tu» vs «você», «estar a fazer» вместо герундия);
  - примерный уровень CEFR.

## 5. Режим 1: PT → RU (видео → перевод голосом)

Сценарий одной карточки:

```
[Всплывающее окно у часов] "Новая фраза — 5 сек"  [Начать] [Позже] [Пропустить]
        │
        ▼
Попытка 1: видео со звуком, БЕЗ субтитров (можно переиграть)
        → голосовой ответ на русском (или ввод текстом)
        → проверка
        ├─ верно   → ✅ оценка Good, показываем перевод/разбор, закрываем
        └─ неверно ▼
Попытка 2: видео + португальские субтитры
        → ответ → проверка
        ├─ верно   → ✅ оценка Hard
        └─ неверно ▼
Показ перевода + разбор → оценка Again, карточка помечается «трудной»
```

**Окно**: Tauri-окно без рамки, поверх остальных, в правом нижнем углу над часами (стиль тоста).
Стандартные уведомления Windows не умеют проигрывать видео, поэтому это своё окно.

**Голос**: push-to-talk по глобальной горячей клавише (по умолчанию `Ctrl+Space`, настраивается;
работает, даже если фокус в другом окне) → запись микрофона (`cpal`, 16 кГц моно) → OpenAI `gpt-4o-mini-transcribe` (самая дешёвая STT, язык `ru`)
→ распознанный текст появляется в редактируемом поле (можно поправить) → проверка.
Поле ручного ввода есть всегда.

**Проверка ответа** (двухступенчатая, чтобы не платить за очевидное):
1. Локально: нормализация и сравнение с эталоном и допустимыми вариантами — точное совпадение → верно.
2. Иначе LLM-судья: оригинал PT + эталон RU + ответ пользователя →
   `{verdict: correct | partial | wrong, feedback: "..."}`. Судья снисходителен к синонимам,
   порядку слов и стилю, строг к смыслу (время, отрицание, лицо).
   `partial` считается как «верно, но Hard».

## 6. Интервальное повторение

Алгоритм **FSRS** (крейт `fsrs`, тот же, что в Anki) — оценки Again/Hard/Good/Easy:

| Исход | Оценка FSRS |
|---|---|
| Верно с 1-й попытки быстро | Easy |
| Верно с 1-й попытки | Good |
| Верно со 2-й попытки (с субтитрами) или `partial` | Hard |
| Не перевёл | Again + флаг `difficult` |

Очередь показа (приоритет сверху вниз):
1. Карточки в стадии заучивания (Again) — возвращаются через ~10–30 мин в тот же день.
2. Просроченные повторения, сначала трудные.
3. Новые — не больше N в день (по умолчанию 10).

«Трудная» карточка — это `lapses ≥ 2` или ручная пометка; флаг снимается после 3 успешных
повторений подряд. Если трудная фраза есть в нескольких клипах, при повторах чередуем клипы.

**Таймер всплывания**: раз в X минут (по умолчанию 25) в заданные часы, при этом НЕ всплываем,
если пользователь неактивен (`GetLastInputInfo`), в полноэкранном приложении / презентации / игре
(`SHQueryUserNotificationState`). Кнопка «Позже» откладывает на 10 мин, есть «не беспокоить на час».
Плюс горячая клавиша «дай карточку сейчас».

## 7. Режим 2: RU → PT (на будущее)

- Показываем русскую фразу → пользователь говорит по-португальски → STT с языком `pt` → LLM-судья.
- В награду и как эталон проигрываем **оригинальный клип** — слышно, как говорит носитель.
- Отдельное SRS-состояние на каждое направление: `(card_id, direction)`.
- Карточка попадает в режим 2 только после того, как выучена в режиме 1 (стабильность > N дней).
- Позже: грубая оценка произношения (сравнение распознанного текста с эталоном).

## 8. Модель данных (SQLite)

```sql
phrases   (id, text_pt, text_ru, alt_ru JSON, notes, cefr, created_at)
clips     (id, phrase_id, file, source_url, source_title, start_ms, end_ms, subs_pt)
reviews   (phrase_id, direction, due, stability, difficulty, reps, lapses, state,
           difficult BOOL, last_review, PRIMARY KEY(phrase_id, direction))
attempts  (id, phrase_id, direction, ts, attempt_no, answer_text, verdict, latency_ms)
sources   (id, url, kind, title, harvested_at)
```

`attempts` — полный лог: по нему потом строим статистику и тюним параметры FSRS.

## 9. Ресурсы и стоимость

- **В простое** работает только процесс трея с таймером — ~10–20 МБ ОЗУ, ~0% CPU.
  Окно (WebView2) создаётся при показе карточки и **уничтожается** после — память освобождается.
  Пока окно открыто, WebView2 занимает ещё ~60–100 МБ — это цена удобного видеоплеера.
- **API OpenAI** за карточку: STT ~10 с речи × 1–2 попытки + один вызов судьи ≈ 0.1 цента.
  50 карточек в день — порядка $1–2 в месяц. Сбор базы на 30 клипов — центы.
