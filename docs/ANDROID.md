# teach-me для Android + синхронизация с десктопом

Статус: предложение, решения приняты (Syncthing; распознавание — системное Android + OpenAI).

## 1. Что хотим

- Тот же тренажёр на телефоне: клип → перевод голосом → вторая попытка с субтитрами → разбор.
- Телефон работает **сам по себе**: офлайн проигрывает клипы, ведёт свои повторения.
- **Синхронизация** с десктопом через Syncthing, бесплатно, без облака и своего сервера:
  - новые фразы и клипы, собранные на ПК, появляются на телефоне;
  - прогресс общий: фраза, выученная на телефоне, не всплывёт на ПК как новая.

Сборщик базы (yt-dlp + ffmpeg) остаётся только на ПК: на телефоне ему не место.

## 2. Приложение: Tauri 2 Mobile

Tauri 2 собирает Android-приложение из того же Rust-кода и того же HTML-интерфейса.

| Часть | Десктоп | Android |
|---|---|---|
| Ядро: SQLite, FSRS, проверка ответов, Claude/OpenAI | `crates/core` | тот же `crates/core` |
| Интерфейс карточки | `ui/index.html` | тот же файл, вёрстка под телефон |
| Видео | `<video>` в WebView2 | `<video>` в Android WebView |
| Напоминания | таймер в трее | уведомление по расписанию (WorkManager, Kotlin-плагин) |
| Голос | `Ctrl+Space` + cpal → OpenAI | большая кнопка «держи и говори» |
| Распознавание речи | OpenAI `gpt-4o-mini-transcribe` | **системное Android SpeechRecognizer** (бесплатно, работает офлайн), OpenAI — запасной вариант |

Почему не нативный Kotlin: пришлось бы второй раз писать FSRS, проверку ответов, клиентов API и интерфейс.
С Tauri общий код — около 80%, на Kotlin пишутся только два маленьких плагина: напоминания и распознавание речи.

Изменения в ядре:
- `reqwest` на `rustls` вместо системного TLS (на Android нет schannel);
- ключи API на телефоне вводятся один раз в настройках (или сканированием QR-кода с ПК), в репозиторий синхронизации **никогда** не попадают.

Как работает на телефоне:
- уведомление «Новая фраза» в активные часы раз в N минут (WorkManager, минимум 15 мин);
- тап по уведомлению → сразу карточка;
- без сети: клип играет, распознавание системное, проверка — точное совпадение с эталоном
  или кнопки «я ответил верно / неверно»; результат попадает в журнал и уйдёт при следующей синхронизации.

## 3. Синхронизация: Syncthing

Выбрано: **Syncthing** — папка синхронизируется напрямую между ПК и телефоном, без облака и без аккаунтов.
Работает и через интернет (через бесплатные ретрансляторы Syncthing), не только в одной Wi-Fi сети.
Условие: изменения переезжают, когда оба устройства одновременно в сети. Пока ПК выключен,
телефон копит свой журнал и отдаёт его при следующей встрече.

- ПК: Syncthing для Windows (`winget install Syncthing.Syncthing` или SyncTrayzor с иконкой в трее).
- Android: **Syncthing-Fork** (Google Play / F-Droid); официальный клиент Syncthing для Android больше не развивается.

### Что лежит в общей папке

```
teach-me-sync/
├─ content/
│  ├─ phrases.jsonl               фразы: uid, текст, перевод, разбор (пишет только ПК)
│  └─ clips/<file>.mp4            клипы (пишет только ПК)
└─ progress/
   ├─ desktop-<id>.jsonl          журнал ответов ПК       (пишет только ПК)
   └─ phone-<id>.jsonl            журнал ответов телефона (пишет только телефон)
```

Объём: ~75 КБ на клип → 1000 клипов ≈ 75 МБ.

### Как устроено, чтобы не было конфликтов

- **Каждый файл пишет только одно устройство.** Контент пишет ПК, журнал прогресса — каждое
  устройство свой. Syncthing никогда не получает одновременных правок одного файла → нет файлов `.sync-conflict`.
- **SQLite не синхронизируется** (база при синхронизации файлом ломается). Каждое устройство держит свою базу,
  а в общей папке лежат только журналы и контент.
- **Прогресс хранится как журнал событий**, а не как состояние:
  `{"id": "...", "phrase": "<uid>", "ts": "...", "dir": "pt-ru", "outcome": "second", "answer": "..."}`.
  Состояние FSRS каждой фразы = воспроизведение всех событий всех устройств по времени.
  Получив одинаковые журналы, оба устройства вычисляют одинаковое расписание.
- **Стабильный uid фразы** — хеш нормализованного португальского текста, одинаковый на всех устройствах.

### Когда приложение читает и пишет папку

- после каждой карточки дописывает событие в свой журнал;
- при запуске и раз в несколько минут подхватывает чужой журнал и новые фразы;
- `harvester mine` на ПК сразу кладёт новые фразы и клипы в `content/`.

### Доступ к папке на Android

Android 11+ не даёт приложениям свободно писать в чужие папки. Варианты:
1. **Разрешение «Доступ ко всем файлам»** — проще всего; приложение личное, ставится не из Google Play,
   поэтому ограничения магазина нас не касаются. Папка `/sdcard/teach-me-sync`.
2. Выбор папки через системный диалог (Storage Access Framework) — аккуратнее, но больше кода на Kotlin.

Начинаем с варианта 1.

### Настройка (один раз)

1. Поставить Syncthing на ПК и Syncthing-Fork на телефон, связать устройства (QR-код с ID устройства).
2. Создать общую папку `teach-me-sync`, указать её путь в `config.toml` на ПК и в настройках приложения на телефоне.
3. Ключи Claude/OpenAI перенести на телефон QR-кодом из десктопа. В общую папку ключи **не попадают**.

## 4. Этапы

1. **Ядро под синхронизацию**: uid фраз, журнал событий вместо прямой записи в `reviews`, пересчёт FSRS из журнала,
   переход на rustls. Миграция текущей базы (126 фраз и уже пройденные карточки сохраняются).
2. **Синхронизация на ПК**: модуль `sync` в ядре (экспорт контента и журнала в общую папку, импорт чужих журналов),
   Syncthing на ПК. Проверяем на второй копии базы.
3. **Android-сборка**: Android Studio/SDK/NDK, Java 17, `rustup target add aarch64-linux-android`,
   `tauri android init`. Карточка и плеер на телефоне, ручная синхронизация.
4. **Плагины на Kotlin**: напоминания (WorkManager + уведомления) и системное распознавание речи.
5. **Удобства**: QR-перенос настроек и ключей, экран статистики.

Риски, которые проверим первыми на этапе 3:
- сборка Android с Windows ARM64: Android Studio и эмулятор на ARM64 Windows поддерживаются не во всех версиях;
  запасной путь — сборка без эмулятора, установка на телефон по USB (adb);
- автозапуск видео со звуком в Android WebView (решается настройкой WebView в плагине).
